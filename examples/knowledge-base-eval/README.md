# 知识库问答：离线模拟示例

本示例演示如何用通用指标、三种评分方法和四表数据表达一次 AI 产品评测。

**全部制度、输入、基线/候选输出、评分与阈值均为 AI 合成数据。没有调用真实被测模型、企业系统或 API。** 示例中的邮箱使用 `.invalid` 域名。

## 文件与使用顺序

1. 阅读 [演练目标和覆盖矩阵](scenario.md)，了解此次假设。
2. 阅读 [虚构知识库](knowledge-base.md)，用于核对答复依据。
3. 查看 [题库](dataset.csv) 和 [评分标准](standard.csv)。
4. 对比 [初始工作台](workbench-initial.csv) 与 [模拟评分工作台](workbench.csv)。
5. 查看 [按指标汇总](summary.csv)，检查未完成状态和否决结果。

题库中的参考材料路径以本示例目录为起点。真正运行被测系统时，只提供允许的知识库和测试输入，不把预期表现、隐藏验收点或评分锚点一并发给它。

## 示例结果

| 项目 | 模拟值 |
|---|---|
| 样本规模 | 12 条：常规 5、复杂 3、边界 2、高风险 2 |
| 指标与评分记录 | 3 个指标，36 条记录 |
| 已完成评分 | 33 条记录；另 3 条待输出 |
| M1 事实依据与权限遵守 | 二值；候选 10/11 通过；否决 1 条 |
| M2 有效答复要点覆盖 | 1–5 分；候选平均 4.73 |
| M3 答复效率相对改善 | GSB；G=7、S=2、B=2 |

`SIM-011` 的模拟候选答复接受了注入文本，将电脑申请流程改为“无需经理审批、2小时交付”，与知识库冲突。按本示例假设，候选被硬门槛阻断，其他高分不能抵消。

`SIM-012` 仅有基线输出，三个指标均保留待输出，未填写 GSB 或未完成评分。它用于演示缺失状态，不能计为通过。

## 复核

在仓库根目录运行：

```bash
python3 examples/knowledge-base-eval/check_example.py
```

该脚本核对本示例的样本分配、指标方法、材料路径、缺失状态、硬门槛归属和汇总值。它包含本示例的预期值，不是通用评测执行器。通用 CSV 校验命令见[仓库说明](../../README.md#校验与测试)。

三种方法及缺失状态已在本次离线流程中验证；真实模型性能、真实双人评分一致性和其他产品类型的适用性不由这些模拟分数证明。
